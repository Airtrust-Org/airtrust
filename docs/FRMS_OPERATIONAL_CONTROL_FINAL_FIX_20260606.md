# FRMS Controle Operacional Final Fix — 2026-06-06

## 1. Problem Observed

On the FRMS > Controle Operacional page, several display and classification issues were identified:

1. **Dates in ISO format**: Dates displayed as `2026-06-05` instead of Brazilian `DD/MM/YYYY`
2. **Technical text leaking to UI**: `Quinzena INCOMPLETO · duty -` shown with raw status codes and technical field names
3. **Misleading "sem escala" classification**: All tripulantes shown as "Check-in sem escala" or "Jornada sem escala" when escala data was simply unavailable for the period
4. **Source label ambiguity**: Three badges (Real/Real/Real) without clear per-badge identification
5. **False "sem escala" alerts**: Alert codes `JORNADA_FRMS_SEM_ESCALA` and `ESCALADO_SEM_JORNADA_FRMS` displayed when no escala data existed

## 2. Root Cause

### 2.1 Date Format
- The `data_operacional` field was rendered directly as-is (ISO string) without any date formatting
- No existing `formatDisplayDate` helper existed in the FRMS module

### 2.2 Quinzena Technical Text
- `status_quinzena` was displayed verbatim (`INCOMPLETO`, `OK`, `CRITICO`)
- `duty_time_periodo_min` used raw field name `duty` as the display label
- When `duty_time_periodo_min` was `null`, `formatMinutesAsHours(null)` returned `-`

### 2.3 False "sem escala" Classification
- The `escala_voo_diaria` table has **only 4 records** (latest: 2026-05-28) and **zero entries for June 2026**
- The `escalado` flag was correctly `false` (no matching escala row exists)
- However, the classification "Check-in sem escala" / "Jornada sem escala" was misleading — it implied the tripulante was checked for escala and found missing, when in fact escala data was entirely unavailable for the period

### 2.4 Source Labels
- Three `SourceBadge` components were rendered side by side with a single caption "Sono / despertar / jornada" below them
- At a glance, it was unclear which badge corresponded to which data source

### 2.5 False Alerts
- `JORNADA_FRMS_SEM_ESCALA` and `ESCALADO_SEM_JORNADA_FRMS` alerts are generated by the backend when `!escalado && teveJornada` or `escalado && !teveJornada`
- When escala data is entirely unavailable, these alerts are misleading noise

## 3. Fixes Applied

### 3.1 Date Format
- Added `formatDisplayDate(isoDate)` helper that manually splits ISO `YYYY-MM-DD` into `DD/MM/YYYY` — no `new Date()` involved, avoiding timezone offset issues
- Applied to all date rendering in the page: table cells and read-ack events

### 3.2 Quinzena Display
- Added `formatFortnightLabel(indicator)` helper that translates status to Portuguese: `INCOMPLETO` → `incompleta`, `OK` → `completa`, `CRITICO` → `critica`, `ATENCAO` → `com atencao`
- Replaced `duty` with `jornada`
- When `duty_time_periodo_min` is `null`, the "jornada" section is omitted entirely instead of showing `-`

### 3.3 Escala-Unavailable Handling
- Added `hasAnyEscalaData(items)` check: if NO visible item has `escalado: true`, escala data is considered unavailable
- When unavailable:
  - **Banner**: Amber warning banner explaining that escala data is missing
  - **Labels**: "Check-in sem escala" → "Check-in (escala indisponivel)", "Jornada sem escala" → "Jornada (escala indisponivel)"
  - **Alerts**: `JORNADA_FRMS_SEM_ESCALA` and `ESCALADO_SEM_JORNADA_FRMS` are filtered out from display

### 3.4 Source Label Clarity
- Replaced single caption row with individual labels above each badge: "Sono", "Despertar", "Jornada"
- Each badge is now visually associated with its data source type
